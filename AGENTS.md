# LIGO Anomaly Research Rules

## Scientific integrity

1. Never fabricate data, results, citations, measurements, or experimental outcomes.
2. Clearly distinguish observed results, calculated results, assumptions, hypotheses, and speculation.
3. Every experimental result must be reproducible from code and recorded parameters.
4. Never alter experimental data to obtain a desired result.
5. Preserve raw data and never overwrite it.
6. Record preprocessing decisions explicitly.
7. Do not claim novelty without performing a literature search.
8. Treat unexpected results as results, not failures to be hidden.

## Software engineering

1. Use Python 3.13 and the project virtual environment.
2. Write modular, readable code.
3. Add tests for important numerical functions.
4. Run tests after substantive changes.
5. Avoid modifying unrelated files.
6. Use Git commits for meaningful completed changes.
7. Never silently change experimental parameters.
8. Record dependencies and configuration.

## Scientific validation

1. Establish baselines before proposing improvements.
2. Use held-out data where appropriate.
3. Avoid data leakage.
4. Report false positives and false negatives where relevant.
5. Test robustness across different observing periods and detectors where possible.
6. Do not interpret statistical anomalies as physical discoveries without independent validation.
7. Prefer multiple independent checks of important findings.

## Research objective

Investigate whether multichannel temporal representations of
gravitational-wave detector data can reveal previously
uncharacterised detector behaviour that is not adequately captured
by conventional morphology-based glitch classification.

The initial project is exploratory. No conclusion about novelty,
physical origin, or scientific significance may be made before the
evidence supports it.
